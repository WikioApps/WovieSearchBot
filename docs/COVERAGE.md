# Feature coverage: original 90-point checklist

This crosswalk maps the research IDs to the shipped implementation. Status describes implemented scope, **not live Telegram/provider certification**. Credentials, account permissions, source publication and configured optional services remain prerequisites.

* **Complete:** the supported workflow is present; the scope column states its boundary.
* **Partial:** useful functionality exists; the omitted portion is explicit.
* **External verification:** exercised during development. Deployment-specific acceptance still requires credentials and representative traffic.

## Verification boundary

Build verification used real MongoDB for multi-catalog behavior and archive round trips, plus simulated Telegram delivery. No test suite is committed, as requested. Actual Telegram sessions, live payments, provider accounts, streams and host-specific limits require deployment verification. These are different from successful syntax/import/database checks.

The measured core peak was **167.94 MiB RSS** on CPython 3.12.14/Linux x86-64 with `MALLOC_ARENA_MAX=2`, real MongoDB outside the measured process and a simulated Bot API, covering startup, seven commands and shutdown **without a user session**. The dependency virtual environment occupied **87 MiB**, excluding interpreter/OS and optional interfaces. This does not establish whole-guest operation within 256 MB RAM/512 MB disk or session/streaming workload capacity. See [deployment](DEPLOYMENT.md).
